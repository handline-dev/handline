# Turborepo layout: React Native app, responsive web, shared packages

Founder's rule (T1798): mobile means a **React Native app**; the web is **responsive**; what they share lives in a **Turborepo**.
This replaces "mobile is a PWA" in `web/README.md` (the PWA in `web/mobile/` is dropped) and extends
`docs/web-ui-design.md` (§4 PC screens, §7 mobile screens). Written against main @2f7de798.

## 1. Decisions

| Question | Decision | Why |
|---|---|---|
| Root | **repo root**: `apps/`, `packages/`, `turbo.json`; `web/` is removed at the end | `contract/` (generated by `contract/generate.py`) joins the workspace where it is, so nothing reaches outside the root with `../` and Metro needs no `watchFolders`. Python and Go stay untouched. |
| Package manager | **pnpm** workspaces with `node-linker=hoisted` | Metro (React Native) is the picky tool; hoisted is the layout it is known to accept. Try isolated installs later. Pin with the `packageManager` field. |
| Mobile | **Expo (React Native), dev client / prebuild, not Expo Go** | The client's WebSocket transport is already React Native-ready. Pairing pins a certificate fingerprint (design §7), which needs a native module Expo Go cannot load (see §6, spike). |
| Web | **React + Vite, a static SPA** | RN is React, so hooks and state code are shared only if the web is React too. No SSR is needed: the page talks to a daemon. Replaces the no-framework, no-build `web/ui/`. |
| Sharing level | **logic and tokens shared; screens written twice** | `react-native-web` would share screens but ties the web's layout to RN primitives; the terminal grid and the PC layout want DOM. Revisit per screen later; nothing here blocks it. |
| Packages | **source-only ("just-in-time")**: `exports` points at `.ts`, no build step per package | Keeps the current Node type-stripping tests; Vite and Metro compile the source themselves. |

## 2. Layout

```
apps/
  web/              React + Vite, responsive: phone, tablet and PC widths from one codebase
  mobile/           Expo app (iOS, Android)
packages/
  client/           @handline/client      DaemonClient, Transport, memoryPair, webSocketTransport  (from web/src)
  client-node/      @handline/client-node unix-socket transport (Node only: tests, Electron main, tools)
  fake-daemon/      @handline/fake-daemon scripted daemon + ws server (Node only: tests, dev)
  app-core/         @handline/app-core    Store, pure screen decisions, key tables; no React, no DOM, no RN
  app-react/        @handline/app-react   DaemonProvider, useStore and selector hooks; React only
  tokens/           @handline/tokens      colors, spacing, type scale, breakpoints as TS constants
  config/           @handline/config      base tsconfigs
contract/           @handline/contract    protocol.ts / protocol.json stay put; a package.json joins them to the workspace
```

Dependency direction is one way: `contract` → `client` → `app-core` → `app-react` → `apps/*`.
`client-node` and `fake-daemon` depend on `client` and are never imported by an app (they appear only in `devDependencies`).
`protocol.ts` stays generated; nothing hand-edits it.

## 3. What is shared, what is not

| Shared (packages) | Source today | Separate per app |
|---|---|---|
| JSON-RPC client, reconnect, cursors, terminal views | `web/src/client.ts`, `transport.ts` | WebSocket construction details (certificate trust: browser uses the page's origin, RN uses the pinned fingerprint) |
| Store: agents, details, notes, open-agent page, terminal view | `web/ui/store.ts` and `web/mobile/store.ts` (two near-copies today) | Persistence of the paired daemon (web: `localStorage`; mobile: secure store) |
| Screen decisions: `dotOf`, `railGroups`, `ago`, `DAEMON_KEYS`, `KEY_STRIP`, which screens exist | `web/ui/model.ts`, `web/mobile/store.ts` | Layout, navigation (web: router; mobile: Expo Router), gestures, safe areas |
| Terminal grid logic: view to lines and cells | `web/ui/terminal-pane.ts` (the DOM part stays) | Rendering (web: `<pre>`; mobile: monospace `<Text>`) and typing (web: hidden textarea + IME events; mobile: `TextInput` + key strip) |
| Tokens and breakpoints | `web/ui/style.css` | Where they land (web: CSS variables from the constants; mobile: used directly) |
| Fake daemon and test helpers | `web/fake-daemon/`, `web/test/helpers.ts` | — |

Responsive web: breakpoints come from `@handline/tokens` (phone < 640, tablet 640–1023, PC ≥ 1024). The PC layout is design §4
(rail, tabs, context panel); at phone width the web shows the design §7 screens (one column, tab bar). Which screens exist is
decided in `app-core`; CSS only decides how they are laid out. Electron (design: web first, Electron wraps the same app) loads the built `apps/web`.

## 4. Tasks and tests

Root `turbo.json` has `test`, `typecheck` and `build`; `test` and `typecheck` depend on the same task of the packages they use
(`^test`). Package tests keep `node --test` on `.ts` (workspace links resolve outside `node_modules`, so type stripping still
applies). Apps add their own: `apps/web` Vite build and a DOM smoke test; `apps/mobile` `tsc` and Jest on pure modules.
The merge gate is `pnpm turbo test typecheck` from the root.

Today's 46 tests: client 17, transports 2, ui-model 9, ui-store 4, serve-ui 4, mobile 10. Where each goes is in §5.

## 5. Migration order

Every step ends with the root gate green, and the tests of code that has not moved yet still run from `web/`
(`web` is a temporary workspace member until step 6). No step changes behavior and moves files in one commit; moves are `git mv`.

1. **Scaffold.** Root `package.json`, `pnpm-workspace.yaml`, `.npmrc`, `turbo.json`, `packages/config`, `contract/package.json`;
   `.gitignore` for `node_modules`, `.turbo`, `dist`. No code moves. Done when `pnpm install && pnpm turbo test` runs the 46 existing tests unchanged from `web/`.
2. **Client and fake daemon.** `web/src` → `packages/client` (minus `node-socket.ts` → `packages/client-node`); `web/fake-daemon` → `packages/fake-daemon`;
   `web/test/helpers.ts` with them. `web/ui` and `web/mobile` import by package name. Done when client 17 and transports 2 pass from the packages and the other 27 still pass.
3. **Core.** `packages/app-core`: one `Store` that covers both old stores (the PC store's `details` and `notes`, the mobile store's `page` and terminal view),
   plus `model.ts` and the key tables. `ui-model` 9 and `ui-store` 4 move over; the store cases in `mobile.test.ts` are folded into `ui-store`'s file.
   `web/mobile/` is deleted here: its 10 tests are either moved (store behavior) or removed with the code they test (`views.ts` HTML), and the commit lists which.
   Then `packages/tokens` and `packages/app-react`. Done when `web/ui` runs on `app-core` and no test was dropped without that list.
4. **Web.** `apps/web` is built beside `web/ui`: shell, agent rail, agent page, terminal pane, then the responsive layouts. `web/ui` is deleted only when
   `apps/web` shows every screen `web/ui` shows (agent rail, header controls, permission card, empty chat, terminal pane with key chips, take/release).
   `serve-ui.ts` goes with it; its 4 tests port to the static server that serves the built `dist` (loopback-only without `--cert`, TLS rule, path hardening).
5. **Mobile.** `apps/mobile` can start once step 3's store API is merged; the TLS-pinning spike (§6) can start at once. First screens: pair, agent list, agent page
   with Chat/Terminal, key strip, permission card, as in design §7.
6. **Cleanup.** Delete `web/`; move `web/README.md` content into `docs/development.md`; fix any doc that names `web/` (none of `development.md`, `web-ui-design.md`, `phase0-findings.md` does today).

## 7. Open points

- **Pairing trust on RN.** RN's `WebSocket` accepts only certificates the OS trusts. A fingerprint-pinned self-signed daemon certificate therefore needs a native hook,
  or the daemon issues a local CA the phone installs. Unit 6 settles it; the answer changes the pairing flow in design §7 and the daemon, not this layout.
- **Who serves the built web app.** `apps/web/dist` is static. Serving it from the daemon's own TLS port keeps the page same-origin (it connects to its own host, as today);
  that is a daemon decision for the daemon team. Until then a small static server in `apps/web` serves it for development.
- **Dependencies.** The repo has had none in `web/`. React, Vite, Expo and TypeScript are the first; the packages `client`, `client-node`, `fake-daemon` and `app-core` stay dependency-free
  so the contract tests do not depend on a UI toolchain.
- **Author's choices, not confirmed by the founder:** repo-root layout, pnpm, Vite over Next, logic-only sharing. Each is one row of §1 and cheap to change before unit 1.
